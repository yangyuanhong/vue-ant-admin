# 高精度大页面 PDF OCR 设计

## 背景

当前 PDF OCR 固定以 `2.0` 倍率将整页渲染为 PNG，再把完整页面交给 PaddleOCR。样例 PDF 的第一页被渲染为 `3284 × 4800`，PNG 约 15.8 MB；解码后的 RGB 像素约占 47 MB，预处理数组和模型中间张量还会进一步放大内存占用。Paddle 检测器提示页面超过 `max_side_limit=4000` 后，Windows 原生推理进程直接退出，没有产生可捕获的 Python 异常。

固定把倍率改成 `1.0` 只能处理当前样例，无法覆盖未来更高 DPI、更大物理尺寸或含小字的 PDF。本设计以最高识别精度为优先，同时为 CPU 内存、GPU 显存、页面尺寸和原生推理崩溃设置明确边界。

## 目标

- 不因 PDF 页面的 DPI 或像素尺寸增长而无限增加整页推理内存。
- 检测阶段允许受控降采样，但文字识别必须尽量使用原始页面细节。
- 利用 NVIDIA GPU 加速多尺度检测和多路复核；GPU 主要改善吞吐量，并通过支持更昂贵的识别策略间接改善精度。
- 单页 Paddle 原生崩溃、超时或显存不足不能杀死 FastAPI 服务。
- 每页完成后立即持久化，服务重启时不重复已完成页面。
- 保存每个文字区域的候选结果、置信度和最终采用的复核策略，支持审计和人工校正。

## 非目标

- 不实现多个 OCR 服务实例共享同一任务队列。
- 不在本阶段实现人工校正 UI。
- 不保证 CPU 与 GPU 的逐位结果一致。
- 不对所有页面并行推理；稳定的显存上限优先于单任务峰值吞吐量。

## 已确认的运行环境

- 操作系统：Windows。
- GPU：NVIDIA GeForce RTX 5070 Ti，16 GB 显存。
- 当前 PaddlePaddle 3.3.1 为 CPU 构建，`paddle.device.is_compiled_with_cuda()` 返回 `False`，实施时必须替换为与驱动、Python 3.11 和 PaddleOCR 3.7.0 兼容的 GPU 构建。
- OCR 长任务必须以单 Uvicorn worker 且不带 `--reload` 的方式运行。

## 总体架构

每页采用“受限全页检测、重叠分块补检、原图裁剪识别、低置信度复核”的混合管线：

```text
PDF 页面
  -> 读取页面元数据并计算渲染预算
  -> 渲染原始精度页面（进程内短生命周期）
  -> 最长边 3200px 的全页检测图
  -> 2048x2048、20% 重叠的补充检测块
  -> 坐标映射、合并与去重
  -> 从原始页面逐个裁剪文字列（8% 边缘）
  -> GPU 主识别
  -> 低置信度文字列三路复核
  -> 古籍阅读顺序排序、持久化页面结果
```

FastAPI 主进程只负责 HTTP、队列和状态查询。每一页的渲染、检测和识别在独立子进程中完成。父进程通过结构化结果文件或进程通信接收结果，再使用现有 SQLite repository 事务提交。

## 页面渲染与资源预算

### 自适应渲染

不再使用固定 `PDF_RENDER_SCALE`。渲染器根据 PDF 页面尺寸、目标 OCR 精度和像素预算计算倍率：

- 识别源图优先按 PDF 原始有效分辨率渲染。
- 单页原始 RGB 像素预算默认上限为 120 百万像素，约 360 MB 裸 RGB；超过预算时不创建完整的超大位图，改为按 PDF 页面坐标直接渲染局部高分辨率裁剪。
- 全页检测图最长边固定为 `3200px`，保持长宽比。
- 任何检测调用的单张输入最长边不得超过 Paddle 检测器的安全上限。

这使普通页面可以复用一张高分辨率源图，而极端页面不会为了少量文字区域生成完整巨幅位图。

### 极端页面的按需裁剪

当完整源图超过像素预算时：

1. 用受限全页图和检测块取得 PDF 页面坐标中的文字框。
2. 针对每个文字框，通过 PyMuPDF clip 按目标 DPI 单独渲染。
3. 每次只保留当前文字列及其复核变体，识别完成后立即释放。

因此内存峰值由“整页最高分辨率”变为“检测图 + 最大单个文字列裁剪 + 模型工作区”。

## 检测、合并与坐标

### 全页检测

- 把页面缩放到最长边 `3200px`。
- 使用古籍检测模型获取主要文字列。
- 所有检测框立即转换为归一化页面坐标或 PDF 页面坐标，后续不依赖检测位图尺寸。

### 重叠分块补检

- 检测块为 `2048 × 2048px`。
- 水平和垂直重叠均为 `20%`。
- 边缘块向页面边界对齐，不用空白填充改变坐标。
- 分块按顺序串行送入一个 GPU 模型实例，避免并发造成显存峰值。

### 合并与去重

- 将所有分块检测框映射回统一页面坐标。
- 对高 IoU、中心线接近或大部分被另一框包含的候选框进行聚类。
- 优先保留覆盖完整文字列的框，而不是简单保留置信度最高但较短的框。
- 对跨块被切开的同列相邻框进行几何合并；合并必须满足方向、横向中心和间距约束。
- 保存来源信息（全页检测或具体分块），用于排查误合并和漏检。

## 高分辨率识别与复核

### 主识别

- 将最终检测框映射回原始页面。
- 四周增加 `8%` 边缘，并设置最小像素 padding，避免切掉笔画。
- 保留彩色裁剪用于朱印判断；增强后的灰度/RGB 裁剪用于正文识别。
- 过长文字列只做保持比例的受限缩放，不从中间裁断。
- 逐列识别并立即释放临时数组，避免一页所有裁剪同时驻留内存或显存。

### 低置信度复核

主识别置信度低于 `0.80` 时，生成三种候选：

1. 原始彩色/灰度裁剪；
2. 自动对比度与轻度对比度增强；
3. 局部对比度增强版本。

选择规则按平均置信度、有效字符数、异常字符比例和古籍文本规范化结果综合评分，不能只比较单一模型置信度。若候选分数接近，保留全部候选并标记 `needsReview=true`，最终正文暂取综合得分最高者。

每个结果保存：

- 页面坐标和原图像素坐标；
- 最终文本、置信度和采用的预处理策略；
- 所有复核候选的文本与置信度；
- 检测来源；
- 是否触发人工复核标记。

## GPU 和进程隔离

### GPU 使用

- 检测器和识别器均配置为 `device="gpu:0"`。
- 单个 OCR worker 同一时刻只运行一页，检测块和文字列均串行推理。
- 启动时验证 Paddle 为 CUDA 构建、GPU 可见且模型可完成一次小型预热推理；验证失败时服务 readiness 失败，不接受新 OCR 任务。
- 不依赖“当前空闲显存”无限扩大输入；输入尺寸仍服从固定像素预算。

### 页面子进程

每页由一个新子进程执行，子进程加载/使用 OCR 模型并写出结构化页面结果。虽然每页重建模型有启动成本，但这是 Windows 下隔离 Paddle 原生崩溃和回收 GPU/CPU 内存最可靠的边界，符合最高精度优先的取舍。

父进程负责：

- 标记页面 `processing`；
- 启动页面子进程并监控退出码、超时和心跳；
- 校验结果完整性后提交 SQLite；
- 无论成功或失败都清理临时文件；
- 子进程异常退出时保持 API 可响应。

页面默认超时为 `15 分钟`。超时后终止整个子进程，而不是只取消 Python await，从而保证底层 Paddle 推理也被终止。

## 失败处理与重试

单页第一次发生下列问题时自动重试一次：

- 非零退出码或无结果的原生崩溃；
- CUDA out of memory；
- 页面超时；
- 结果文件损坏或字段缺失。

重试时降低检测分块到更保守的尺寸，并清理 GPU 上下文。识别裁剪仍保持原始清晰度，因此降级主要影响检测吞吐和上下文，不主动降低文字识别分辨率。第二次失败后，将该页及任务标记为 `failed`，保存退出码、阶段、最后心跳、重试参数和可读错误信息。

服务启动时沿用现有恢复规则：`processing` 任务回到 `queued`，`processing` 页面回到 `pending`，已完成页面保持不变。长任务禁止 `--reload`，README 和启动脚本必须明确这一点。

## 数据模型调整

现有页面结果继续保存最终 `text` 和 `items_json`。`items_json` 扩展但保持现有顶层 `text`、`score`、`box` 字段兼容，并增加：

- `sourceBox`：归一化或 PDF 页面坐标；
- `strategy`：最终预处理/复核策略；
- `candidates`：候选文本、置信度及策略；
- `needsReview`：是否建议人工核对；
- `detectionSource`：全页或分块标识。

页面或任务错误信息增加机器可读错误类型，但不要求在本阶段新增数据库表。若单个 `items_json` 过大，再在后续迁移为独立区域表，本次不提前扩展范围。

## 可配置项

提供环境变量并使用上述值作为默认值：

- `OCR_DEVICE=gpu:0`
- `OCR_FULL_PAGE_MAX_SIDE=3200`
- `OCR_DETECTION_TILE_SIZE=2048`
- `OCR_DETECTION_TILE_OVERLAP=0.20`
- `OCR_SOURCE_MAX_PIXELS=120000000`
- `OCR_CROP_PADDING_RATIO=0.08`
- `OCR_REVIEW_CONFIDENCE=0.80`
- `PDF_PAGE_OCR_TIMEOUT_SECONDS=900`
- `PDF_PAGE_MAX_ATTEMPTS=2`

配置启动时一次性解析和校验；非法值使服务启动失败，不在运行中静默回退。

## 测试策略

### 单元测试

- 自适应倍率和像素预算计算，包括超宽、超高和超大 DPI 页面。
- 分块覆盖完整页面、边界对齐和 20% 重叠。
- 分块坐标映射回页面坐标。
- 重复框、包含框和跨块文字列合并。
- 8% padding 不越界。
- 低置信度触发三路复核，高置信度不触发。
- 候选综合评分和 `needsReview` 判定。
- 子进程超时、崩溃、OOM、损坏结果及第二次失败的状态迁移。

### 集成测试

- 使用合成大页面 PDF，证明不会创建超过像素预算的完整源位图。
- 使用真实样例 `ancient-book.pdf` 完成第一页，不发生进程退出；状态接口在推理期间持续响应。
- 人为终止页面子进程，确认 API 存活且自动重试。
- 完成若干页后重启服务，确认从第一张未完成页继续。
- GPU 预热失败时 readiness 明确失败。

### 精度验收

选取包含小字、淡墨、印章、页面边缘文字和跨分块文字列的固定页集，建立人工校对基准。与当前 `1.0` 倍整页方案比较：

- 字符准确率不得下降；
- 小字与淡墨区域召回率应提高；
- 不得把朱印文字混入正文；
- 跨块文字列不得重复或被截断；
- 每个错误或低置信度结果可以追溯到候选和识别策略。

## 运行与可观测性

每页记录结构化阶段日志：渲染、全页检测、分块检测、框合并、主识别、复核、持久化。日志包含任务 ID、页码、输入尺寸、分块数、候选框数、最终框数、各阶段耗时、CPU 内存峰值、GPU 显存峰值、尝试次数和子进程退出码。

状态查询必须只做 SQLite I/O，不获取推理锁。健康检查区分进程存活与 GPU/模型就绪，保证“端口仍监听但 OCR worker 已死”的情况能够被监控发现。

## 实施顺序

1. 建立兼容 RTX 5070 Ti 的 Paddle GPU 环境，并添加启动预检。
2. 抽离页面渲染预算、坐标变换、分块与合并模块，以纯函数测试覆盖。
3. 实现高分辨率逐列识别和低置信度复核。
4. 把单页管线移入可终止子进程，接入退出码、心跳和一次自动重试。
5. 接回现有 SQLite worker，补充结构化日志和任务恢复测试。
6. 用真实 PDF 建立精度与资源基线，再调整阈值；阈值变化必须通过固定基准集验证。
